Kontext

Proč Čajomil vznikl

Spravuji čajovny ve firmách a školách. Každá objednávka, každá komunikace s čajomily — vše ručně.

😤

Problém: správce

Ruční objednávání na teamountain.cz každé 2 měsíce. Nevidím spotřebu. Komunikace s čajomily roztříštěná přes Slack, email, osobně.

😕

Problém: čajomil

Neví jak připravit konkrétní čaj. Neví kdy budou doplněny zásoby. Nemá jak říct "chci objednat tento čaj".

🍵

Řešení: Čajomil app

Mobilní app pro čajomily — objevování, požadavky, notifikace. Propojená s admin systémem pro správce.

🫖

Řešení: Admin systém

Dashboard spotřeby, objednávkový agent s AI návrhem, čajový katalog z automatického scraperu teamountain.cz.

SYSTEM-PLAN.md — ukázka z dokumentu 
# "Vsichni mohou cajovat" — System Plan

> Metodika: Research → Product Decisions → UX Constraints → Implementation
> Princip: Hierarchicke rizeni kontextu — kazda faze predava jen to, co dalsi potrebuje

## FAZE 3: UX DEFINITION (explicitni omezeni)

### 3.1 UX principy

PRAVIDLA PRO KAZDE ROZHRANI:
1. Mobile-first — cajomilove pouzivaji telefon v kuchynce
2. Jedna akce na obrazovku — zadne dashboardy plne dat
3. Vizualni caj — velke fotky, barvy caje jako UI barvy
4. 3-klik maximum — od "chci caj" k "pozadavek odeslan"
5. Tichy system — notifikace jen kdyz je to relevantni

### 3.2 Obrazovky cajomila (Mobile)

[1] DOMOVSKA OBRAZOVKA
    ├── Dnesni doporuceni (1 caj, velka fotka)
    ├── Tvoje oblibene (horizontalni scroll)
    └── [CTA] "Dochazi ti caj? Rekni nam"

[2] DETAIL CAJE (= mini landing page)
    ├── Hero fotka
    ├── Priprava (teplota, cas, gramaz) — vizualne
    ├── Ucinky (tagy: energie, klid, traveni...)
    └── [CTA] "Chci tento caj" → pozadavek

[4] OBJEVOVANI
    ├── Karty caju (swipe jako Tinder)
    └── "Tohle neni pro me" / "Chci zkusit"
Workflow

Design → Kód → Deploy

Celý proces od prvního screenu po živou URL pomocí Claude Code + Pencil.dev MCP.

1

Pencil.dev — design systém

Otevřel jsem pencil-shadcn.pen — soubor se 87 shadcn/ui komponentami. Claude Code přes MCP nástroje četl strukturu a navrhoval screeny přímo do canvasu.

get_editor_state() find_empty_space_on_canvas() batch_design(operations) get_screenshot(nodeId)
2

Admin desktop screeny (1440×900)

3 admin screeny navrženy v Pencilu z reusable shadcn komponent — Sidebar, DataTable, Card, Badge, Progress. Každý screen vizuálně ověřen přes get_screenshot.

[A] Dashboard [B] Objednávkový agent [C] Čajový katalog
3

Mobilní app — Vite + React + Framer Motion

7 mobilních screensů (390×844) s micro-animacemi. Spring animace, AnimatePresence přechody, drag-to-swipe karty, stagger efekty. Navigace propojená přes App.tsx.

type: 'spring' as const AnimatePresence mode="wait" useMotionValue / useTransform
4

PACT workspace — organizace projektu

Projekty, agenty, kontext a nástroje uloženy do strukturované workspace. Cursor rules pro automatické načítání kontextu při práci v každém projektu.

.cursor/rules/ Context/identity/ Context/goals/ Tools/
5

GitHub Pages deploy

Vite build s base: '/cajomil-app/' + gh-pages -d dist. Automatický deploy na každý npm run deploy.

npm run build npm run deploy → cajpij.github.io/cajomil-app/
